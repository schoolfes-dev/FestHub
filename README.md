# FestHub

**FestHub** は、文化祭・学校行事・地域イベントなどの運営を支援する、オープンソースのイベント運営基盤を目指すプロジェクトです。

電子スタンプラリーや入退場管理など、イベントに必要な機能を共通の API と Web アプリケーションを通じて提供し、学校・団体ごとに使い方を選べる仕組みを開発します。

> **現在は構想・初期開発段階です。**
>
> 以下に記載する機能や提供形態は計画中のものであり、利用可能な状態とは限りません。

## 目指すもの

- **手軽に使える**：専用アプリのインストールを前提とせず、Web ブラウザから利用できる。
- **既存システムと連携できる**：API を利用して、各学校・団体が開発したシステムにも組み込める。
- **運営者が設定できる**：将来的には、管理画面からイベントの設定・運用を行える。
- **さまざまなイベントで使える**：特定の学校や行事に依存しない、再利用可能な基盤にする。

## 検討中の機能

| 機能 | 概要 |
| --- | --- |
| 電子スタンプラリー | QR コードなどを利用したチェックポイント巡りと達成状況の管理 |
| 入退場管理 | 来場者の受付、入場・退場の記録 |
| 整理券 | 整理券の発行や利用状況の管理 |
| 会場マップ | 企画・施設・チェックポイントなどの案内 |
| 謎解き・周遊企画 | スタンプラリーの仕組みを応用したイベント体験 |

※ 機能の内容や実装順序は、開発コミュニティでの議論を通じて決定します。

## 提供を目指す形態

FestHub では、次の利用方法を想定しています。

1. **API の利用**：既存の Web サイトやアプリケーションから FestHub の機能を利用する。
2. **標準 Web アプリケーションの利用**：独自のフロントエンドを開発せずに、来場者向け・運営者向け画面を利用する。
3. **ホスティングサービスの利用**：各団体でサーバーを用意せずに、提供された環境を利用する。

まずは共通 API 基盤と最小限の機能の実装を進め、実際の学校・イベントでの検証を通じて改善する方針です。

## 開発への参加

FestHub は、開発に関心のある方の参加を歓迎します。プログラミングだけでなく、UI/UX 設計、ドキュメント作成、テスト、イベント運営の知見の共有なども重要な貢献です。

詳しい参加方法は、 [CONTRIBUTING.md](CONTRIBUTING.md) を参照してください。

### Discord と GitHub の役割

- **Discord**：アイデア出し、企画、仕様検討、方針決定、日々の相談・進捗共有を行います。
- **GitHub Issues**：実装することが決まったタスクやバグを管理します。
- **GitHub Pull Requests**：コードやドキュメントの変更を提案・レビューします。
- **GitHub のドキュメント**：開発に必要な確定済みの仕様や手順を記録します。

開発方針や機能の提案については、まず Discord でご相談ください。

- [Pull Requests](https://github.com/schoolfes-dev/festhub/pulls)

## 開発状況

現在はプロジェクトの立ち上げ段階です。共通 API 基盤の設計と、電子スタンプラリーを中心とした最小構成での動作検証を初期の開発対象として検討しています。

将来的には、実際のイベントでの実証を経て、他の学校・団体でも利用しやすい仕組みを目指します。
